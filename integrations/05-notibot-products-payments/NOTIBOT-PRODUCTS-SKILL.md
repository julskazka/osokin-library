# Товары и оплаты Notibot

Применяй, когда нужно связать материалы, уроки, курсы, уровни, функции или кнопки проекта с товарами Notibot и проверить, какие товары текущий пользователь оплатил.

## Сохрани существующий проект

Не меняй дизайн, шрифты, фон и архитектуру ради подключения оплат. Этот архив — комплект интеграции, не макет интерфейса. Не добавляй формы или передачу персональных данных без необходимости.

## SDK

В head страницы подключи ровно один официальный SDK:

```html
<script src="https://list.notibot.ru/notibot-bridge.js?v=2.27"></script>
```

Если уже подключён — переиспользуй. Если есть старый мост, сначала изучи его функции и аккуратно мигрируй необходимые вызовы. Не устанавливай второй мост и не копируй внутреннюю логику SDK. js/notibot-bridge.js в архиве — справочная копия, не дополнительный runtime.

## Строго разрешённые методы проверки оплаты

```js
const paid = await window.notibot.hasPurchased(productId);
const productIds = await window.notibot.getPurchasedProducts();
const freshProductIds = await window.notibot.getPurchasedProducts({forceRefresh:true});
```

- hasPurchased принимает строку productId и возвращает Promise<boolean>.
- getPurchasedProducts возвращает Promise<string[]>: оплаченные товары пользователя в текущем магазине.
- Всегда await; не проверяй Promise как boolean.
- Не передавай userId, Telegram ID, MAX ID или username. SDK и бэкенд определяют пользователя автоматически.
- Не выдумывай checkOrder, isPaid, getUserPurchases и другие методы SDK.
- Проверь наличие window.notibot. Наличие объекта SDK не равно готовности: дождись его onUpdate перед запросом.
- Для каталога получи список один раз и сопоставь реальные product_id. Для одного товара подходит hasPurchased.

## Связь товаров

Изучи данные проекта и реальные ID магазина. Задай явную таблицу соответствий: материал → product_id → access_page_id/purchase_page_id. Не используй pageId вместо productId. Один товар может открывать несколько материалов только если это подтверждено моделью продукта.

Бесплатные материалы не зависят от оплаты. Купленный товар открывает связанный материал и скрывает/заменяет кнопку покупки. Некупленный ведёт на страницу покупки. Не выводи технические ID посетителям.

## Обновление и ошибки

- После возвращения с оплаты и по кнопке повтора используй await getPurchasedProducts({forceRefresh:true}).
- Обрабатывай Promise rejection и отсутствие ответа: ограничь ожидание (например, 10 секундами), дай повторный запрос.
- На новом контексте пользователя сразу сбрасывай предыдущие доступы; игнорируй устаревшие ответы асинхронных запросов.
- До успешной проверки не выдавай платный доступ. На ошибке он остаётся закрытым.
- Не показывай «Покупки проверены», «Ожидаем подключения к Notibot» и другие служебные статусы. При реальной ошибке допустим короткий человеческий текст и кнопка повтора.
- Вне Notibot проект должен работать автономно без ложного подтверждения оплат. Демопокупки, если нужны для теста, явно обозначай и изолируй.

SDK v2.27 преобразует неуспешный серверный ответ в []: это неотличимо от отсутствия покупок. Не утверждай, что клиент может диагностировать такой ответ как ошибку; в обоих случаях доступ не выдаётся.

## Навигация

Для перехода на страницу внутри Notibot:

```js
window.notibot.openLink('https://t.me/post#REAL_PAGE_ID');
```

Сохраняй выданные пользователем внутренние ссылки и реальные ID. Не открывай новую вкладку и не перезапускай MiniApp через startapp для внутреннего перехода. Дизайн кнопок оставь как в проекте.

## Проверка

Проверь: оплаченный/неоплаченный товар, бесплатный материал, пустой список, неизвестные товары, возврат после оплаты, смену пользователя, таймаут/ошибку, переход в том же окне, автономный режим. Укажи, что проверено имитацией и что — внутри настоящего магазина. Не называй клиентский интерфейс защитой самих закрытых материалов: ограничения на материалы остаются на стороне платформы/сервера.
