# Notibot: переносимый комплект проверки оплат

Рабочий способ проверки оплат через официальный SDK v2.27+. Передайте весь архив в другой проект и попросите подключить проверку оплат, сохранив дизайн. Ключи, токены и userId не нужны.

## Где работает

На HTML-страницах, открытых внутри Notibot и получивших контекст текущего магазина/пользователя. Это позволяет проверять покупки в других MiniApp Notibot, но не в произвольной внешней странице без Notibot. Для каждого проекта укажите реальные ID его товаров в соответствующем магазине. Product ID и ID страницы — разные значения.

## Файлы

- `FOR_AI.md` — краткие инструкции для переноса в другой проект.
- `js/notibot-payments.js` — необязательный готовый помощник: асинхронная проверка списка, таймаут, обновление после возврата, сброс доступов при новом контексте, игнорирование устаревших ответов. Второй мост не создаёт.
- `js/notibot-message-guard.js` — фильтр сообщений SDK: протокол принимается от родительского окна, а не от посторонних окон.
- `examples/integration.html` — минимальный пример с тремя ID-заглушками для замены. Это пример логики, не дизайн для замены вашего интерфейса.

Официальный SDK не скопирован в архив: в head проекта подключается актуальная версия по адресу Notibot.

## Подключение

В head, один раз и в таком порядке:

```html
<script src="./js/notibot-message-guard.js"></script>
<script src="https://list.notibot.ru/notibot-bridge.js?v=2.27"></script>
<script src="./js/notibot-payments.js"></script>
```

Если SDK уже есть, не подключайте второй. Уберите старый мост, который создаёт/заменяет `window.notibot`. Сам помощник покупок необязателен: можно пользоваться официальными методами напрямую.

## Официальные методы

```js
// После получения контекста через onUpdate:
if (window.notibot) {
  const paid = await window.notibot.hasPurchased('REAL_PRODUCT_ID');
  const ids = await window.notibot.getPurchasedProducts();
  const freshIds = await window.notibot.getPurchasedProducts({ forceRefresh: true });
}
```

Не передавайте userId. Оба метода асинхронны. Для каталога удобнее получить весь список один раз и сопоставить товарные ID. `hasPurchased` подходит для одного товара. Метод `onUpdate` используется для момента получения контекста; факт существования `window.notibot` сам по себе не означает подключение к магазину.

## Готовый помощник

```js
const payments = NotibotPayments.create({
  onChange(state) {
    const paid = state.status === 'ready' &&
      state.purchasedProductIds.includes('REAL_PRODUCT_ID');
    // Обновить существующие элементы вашего интерфейса.
  }
});
await payments.refresh({ forceRefresh: true }); // Кнопка повторного запроса
```

`NotibotPayments` — наш вспомогательный объект, НЕ метод SDK. Его методы: `getState()`, `refresh({forceRefresh:true})`, `dispose()`. Состояния помощника: waiting, loading, ready, error, unavailable, standalone. Служебные состояния waiting/loading/ready не нужно показывать людям текстом. При ошибке можно дать короткое понятное сообщение и кнопку повтора.

Помощник сам ожидает onUpdate и обновляет покупки без кэша после возвращения по focus/visibility/pageshow. Покупки не сохраняются локально. При смене контекста предыдущие доступы сразу очищаются. По умолчанию запрос ограничен 10 секундами. Не создавайте больше одного помощника на экземпляр приложения; при размонтировании вызывайте dispose().

## Навигация

Внутри Notibot используйте существующий openLink и реальные ID страниц:

```js
window.notibot.openLink('https://t.me/post#REAL_PAGE_ID');
```

Для купленного товара — ID страницы материала, для некупленного — ID страницы покупки. Не заменяйте productId на pageId в проверке покупки. Не запускайте MiniApp повторно через startapp и не ставьте target=_blank для внутренних переходов.

## Важные границы

- SDK проверяет оплаченные товары текущего магазина, а не любые платежи в интернете. Сопоставление ID в другом магазине нужно настроить отдельно.
- Пример не содержит настоящих товаров или материалов. Перед использованием замените все `REPLACE_WITH_...`.
- На ошибке/ожидании закрытые материалы остаются закрытыми. Бесплатные материалы не зависят от покупок.
- SDK v2.27 преобразует неуспешный серверный ответ в пустой список. Клиент не может отличить его от отсутствия покупок. Платный доступ не выдаётся в обоих случаях.
- Клиентский интерфейс не заменяет защиту самих материалов на стороне Notibot. Не размещайте секретные данные в скрытом HTML и не считайте query string доказательством оплаты.
- Проверка в библиотеке подтверждена пользователем внутри Notibot. После переноса в другой проект проверьте его отдельно: купленный товар, некупленный, возврат после оплаты, другой пользователь, сетевой сбой и переход в том же окне.
