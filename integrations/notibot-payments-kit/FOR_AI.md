# Задача при переносе комплекта

Подключи проверку оплаченных товаров Notibot к существующему проекту, сохранив его дизайн и архитектуру. Это комплект интеграции, а не указание перестраивать интерфейс.

1. Прочитай README.md и реальный код проекта. Найди подключённые мосты и текущий каталог товаров.
2. В head должен быть ровно один официальный SDK: https://list.notibot.ru/notibot-bridge.js?v=2.27 . Не устанавливай второй мост и не копируй внутренности SDK. При миграции со старого адаптера сохрани нужные навигационные сценарии.
3. Для проверки оплат разрешены только реальные методы SDK: await window.notibot.hasPurchased(productId), await window.notibot.getPurchasedProducts(), await window.notibot.getPurchasedProducts({forceRefresh:true}). Никаких выдуманных checkOrder/isPaid/getUserPurchases. Не передавай userId.
4. До запроса проверь наличие window.notibot и дождись onUpdate. В обычном браузере без контекста Notibot оставь безопасный автономный режим; тестовые покупки нельзя показывать как реальные.
5. Используй реальные product_id из данных пользователя. Не выдумывай ID. Если их нет — запроси только недостающие ID. Product ID не равен ID страницы оплаты или ID страницы материала.
6. Можно подключить js/notibot-payments.js: он использует официальный SDK и не является вторым мостом. Публичный интерфейс этого помощника описан в README.md. Если проект уже имеет аналогичный рабочий слой, добавь проверку в него без дублирования.
7. После оплаты/возврата и по явному повтору запрашивай forceRefresh:true. Обрабатывай ожидание, ошибку, таймаут, новый контекст пользователя и устаревшие ответы. Не выдавай доступ по неподписанному userId из адреса, локальному флажку или просмотру оплаты.
8. Не выводи посетителям «Покупки проверены», «Ожидаем подключения к Notibot» и другие служебные статусы. При реальной ошибке допустим короткий понятный текст и повторный запрос. Не выводи личные данные без отдельного требования.
9. Для внутренних страниц сохрани openLink('https://t.me/post#PAGE_ID'), чтобы не перезапускать MiniApp через startapp. Не добавляй новую вкладку.
10. Протестируй купленный/некупленный товар, бесплатные материалы, сброс кэша после оплаты, смену пользователя и отказ запроса. Отдельно укажи, что проверено имитацией, а что — в настоящем магазине Notibot. Не называй клиентскую подсветку серверной защитой материалов.
