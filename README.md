# Библиотека эфиров Виталия Осокина

24 эфира (5 бесплатных и 19 платных), компактное зеркальное дерево, исходная фотография и обложка, едва заметные звёздочки. Фильтры и порядок каталога сохранены.

## Запуск

```sh
python3 -m http.server 8000
```

Откройте http://localhost:8000. Данные и изображения подключены относительными путями. SDK Notibot v2.27 подключается по официальному HTTPS-адресу в head.

## Notibot и оплаченные товары

`src/access-provider.js` после инициализации SDK ожидает `window.notibot.getPurchasedProducts()` и сопоставляет результат с `product_id` 19 платных эфиров. Бесплатные доступны независимо от списка. `userId` не передаётся, пользователь определяется SDK. Тестовые переключатели доступны только вне Notibot.

После возврата в библиотеку (focus, visibilitychange, pageshow) и по кнопке «Обновить доступ» выполняется запрос с `{forceRefresh:true}`. При новом контексте пользователя старые доступы сбрасываются, устаревшие ответы не применяются. При ожидании/ошибке платные переходы заблокированы. Таймаут проверки — 10 секунд, доступен повторный запрос.

Переходы внутри Notibot — `openLink('https://t.me/post#ID')`, без новой вкладки. Вне платформы сохранены обычные startapp-ссылки и явно обозначенный деморежим. Профиль и идентификаторы не выводятся и не сохраняются.

SDK v2.27 преобразует неуспешный ответ сервера в `[]`: для библиотеки это неотличимо от отсутствия покупок, платный доступ в обоих случаях не выдаётся. Закрытые материалы должны оставаться защищены на стороне Notibot; клиентская подсветка не заменяет их защиту.

## Готовый HTML

Скачайте `notibot-library.zip`, распакуйте и замените HTML страницы Notibot целиком. Фотография, дизайн и каталог встроены; единственная внешняя зависимость этого HTML — официальный SDK:

```html
<script src="https://list.notibot.ru/notibot-bridge.js?v=2.27"></script>
```

Инструкция в `NOTIBOT-SETUP.txt`. Пересборка из исходников:

```sh
python3 scripts/bundle-notibot.py build
```

## Проверки

`npm test` (Node.js 20+) проверяет каталог, фильтры, внутренние ссылки, геометрию, асинхронное получение покупок, сопоставление product_id, сброс кэша, ошибку и таймаут. Браузерные проверки выполнены с реальным кодом SDK v2.27 и имитацией родительского Notibot: покупки/пустой список, обновление после оплаты, смена пользователя, ошибка, короткие ссылки без новых окон. Обычный сайт и собранный HTML проверены отдельно, мобильные ширины — 320/375 px, широкие — 768/1280 px.

Настоящий аккаунт магазина и фактическая оплата не проверялись. Перед запуском проверьте внутри Notibot аккаунты с известной покупкой и без покупки, возврат после оплаты и используемые режимы Inline/App/Portal. Актуальность ссылок и товарных ID нужно сверять с магазином.

## Комплект для связи товаров в других проектах

`05-notibot-products-payments.zip` — отдельный архив по образцу комплекта подключения Notibot: README, NOTIBOT-PRODUCTS-SKILL.md, QUICK-RECIPES и справочная копия официального SDK v2.27. Это не библиотека эфиров: в нём нет её дизайна, каталога или товарных ID. Передайте архив ИИ вместе с другим проектом, чтобы подключить проверку его товаров и оплат.

Служебные сообщения об ожидании и успешной проверке в библиотеке скрыты; при сбое остаётся понятное сообщение и повторный запрос.
