БИБЛИОТЕКА ДЛЯ NOTIBOT — SDK v2.27
20 эфиров; исключены «Места силы 2.0», «Род. Эфир 2» (две части), «Справляться с будущим 2», «Нет проблем». «Род» имеет одну страницу покупки, один товар и одну страницу после оплаты.

1. Создайте/откройте страницу Notibot для собственного HTML.
2. Распакуйте notibot-library.zip и вставьте всё содержимое notibot-library.html. Замените предыдущую версию целиком.
3. Сохраните страницу и откройте её внутри Notibot. Требуется доступ к https://list.notibot.ru/notibot-bridge.js?v=2.27 — актуальный SDK подключён в head. Локальные фотография, стили и каталог встроены в HTML.
4. Покупки проверяются автоматически; служебные надписи о проверке и подключении не показываются. «Доступные мне» = 4 бесплатных + эфиры по оплаченным product_id текущего магазина. «Куплен» показывается только для совпавшего товара.
5. Проверьте с аккаунтом с покупкой и аккаунтом без покупок. Известный оплаченный эфир должен светиться и вести на access_page_id, неоплаченный — на purchase_page_id.
6. После оплаты вернитесь в библиотеку. События focus/visibility/pageshow запрашивают getPurchasedProducts({forceRefresh:true}). Также доступна кнопка «Обновить доступ».
7. Проверьте Inline/App/Portal, которые используете: прокрутку, возврат, высоту и переход в том же окне.

Вызов покупок выполняется только после onUpdate официального SDK. Используется await window.notibot.getPurchasedProducts(), без userId. Все 16 платных эфиров имеют уникальные product_id. Лишние товары магазина игнорируются. Идентификаторы не выводятся и не сохраняются в браузере. Реального профиля в интерфейсе пока нет.

При ожидании/ошибке платные переходы блокируются, бесплатные работают после подключения. Запрос ограничен 10 секундами; при ошибке нажмите «Обновить доступ». SDK v2.27 сам преобразует неуспешный ответ сервера в пустой список: библиотека не может отличить такой ответ от отсутствия покупок; в обоих случаях платный доступ не выдаётся.

Переходы через официальный openLink с https://t.me/post#ID. Короткие ID страниц сохранены. Вне Notibot показывается явно обозначенный деморежим, SDK покупок не вызывается, обычные startapp-ссылки остаются для автономного открытия.

Клиентская индикация не заменяет ограничения на доступ к самим закрытым материалам в Notibot. Получение оплаченных заказов и определение пользователя обеспечивает официальный SDK и его бэкенд. Токены и серверные ключи библиотеке не нужны.

Проверка разработки: реальный код SDK v2.27 с имитируемым родительским окном Notibot (покупки, пустой список, обновление после оплаты, смена пользователя, ошибка/таймаут, навигация). Настоящий аккаунт магазина и фактическая оплата автоматически не проверялись.
